Okta 16 endpoints · 15 controls

Auth OAuth 2.0 for Okta API: service app using client_credentials with private_key_jwt against https://<org>.okta.com/oauth2/v1/token, granted granular read scopes (okta.users.read, okta.logs.read, okta.apps.read, okta.groups.read, okta.factors.read, okta.policies.read, okta.authorizationServers.read, okta.eventHooks.read, okta.networkZones.read, okta.roles.read). Legacy API token via 'Authorization: SSWS <token>' also works but is not least-privilege.
Base URL https://<org>.okta.com/api/v1

MethodEndpointPurpose
GET/usersFull identity inventory: lifecycle status (STAGED/PROVISIONED/ACTIVE/SUSPENDED/DEPROVISIONED), profile, credential provider, and lastLogin per user.
GET/users/{userId}/factorsEnrolled authenticators per user: factorType, provider, enrollment status - the MFA-coverage and credential-binding record.
GET/users/{userId}/rolesAdmin role assignments for a user (SUPER_ADMIN, ORG_ADMIN, custom roles) with assignment status and timestamps.
GET/users/{userId}/groupsGroup memberships per user, supporting periodic entitlement review.
GET/groupsGroup inventory - the entitlement containers that drive application access.
GET/groups/rulesGroup rules that automate entitlement assignment from attribute expressions (e.g., department).
GET/appsApplication instances (SSO-integrated SaaS and supplier-provided services): label, status, signOnMode, created.
GET/apps/{appId}/groupsGroup assignments per app with priority, showing assignment scope used to rank app criticality.
GET/policies?type=PASSWORDPassword policies: complexity, history, age, lockout - the credential-strength standard.
GET/policies?type=MFA_ENROLLMFA enrollment policies: which authenticators are required, for which groups.
GET/policies?type=OKTA_SIGN_ONGlobal session policies: session lifetime, idle timeout, and factor requirements.
GET/authorizationServersCustom authorization servers issuing OAuth/OIDC tokens for APIs.
GET/authorizationServers/{authServerId}/credentials/keysToken signing keys (JWKS) with status ACTIVE/NEXT/EXPIRED and rotation expiry - assertion integrity evidence.
GET/logsSystem Log query (since/until/filter/q, cursor pagination): authentication, session, lifecycle, admin, policy-evaluation, and threat events.
GET/eventHooksEvent hooks streaming System Log events to SIEM/SOAR endpoints, with ACTIVE status and subscribed event types.
GET/zonesNetwork zones (IP/Dynamic) consumed by sign-on policies to gate access by source network.

Jamf Pro 20 endpoints · 13 controls

Auth OAuth2 client-credentials grant for a Jamf Pro API Client: POST {base_url}/v1/oauth/token with form-encoded client_id/client_secret (grant_type=client_credentials) returns a bearer access_token (short-lived, ~30 min default TTL; re-request when expired). Alternative: POST {base_url}/v1/auth/token with HTTP Basic credentials of a Jamf Pro API-role account; refresh via POST /v1/auth/refresh-token and revoke via POST /v1/auth/invalidate-token. The same bearer token is honored by classic /JSSResource endpoints (which live at the instance root, outside /api). Provision a least-privilege API role with only Read privileges for the endpoints below (Read Computers, Read Mobile Devices, Read Smart Computer Groups, Read Static Computer Groups, Read Policies, Read User-Initiated Enrollment, View Local Admin Password Audit History, Read Device Compliance Information); write commands (POST /v2/mdm/commands) are approval-gated per playbook decision D7 and are never issued autonomously.
Base URL https://<instance>.jamfcloud.com/api

MethodEndpointPurpose
POST/v1/oauth/tokenOAuth2 client-credentials exchange: client_id + client_secret -> bearer access_token for an API Client (least-privilege, secret-rotatable).
POST/v1/auth/tokenBasic-auth token exchange: HTTP Basic (API-role username/password) -> bearer JWT; supported alternative for tenants not using API Clients (Jamf recommends API Clients as more secure and has not deprecated this path).
POST/v1/auth/refresh-tokenRefresh an unexpired bearer token issued via /v1/auth/token.
POST/v1/auth/invalidate-tokenRevoke the current bearer token on integration teardown/rotation.
GET/v1/computers-inventoryPaginated macOS computer inventory (totalCount/results envelope; page, page-size, sort, RSQL filter params). section=GENERAL,HARDWARE,APPLICATIONS,SECURITY,PURCHASING,... trims the payload to the sections a control needs.
GET/v1/computers-inventory/{id}Single computer inventory record for drill-down on one device.
GET/v1/computers-inventory-detail/{id}Full detail record: applications, localUserAccounts, certificates, configurationProfiles and groupMemberships (groupId/groupName/smartGroup) for one computer.
GET/v2/mobile-devicesPaginated iOS/iPadOS/tvOS device inventory with RSQL filter; the v1 equivalent is deprecated, use v2.
GET/v2/mobile-devices/{id}/detailFull mobile device detail incl. security block (activationLockEnabled, passcodeCompliant, hardwareEncryption, jailBreakDetected) and managementId used for MDM commands.
GET/v2/patch-software-title-configurationsList of configured patch titles (third-party + Apple) that Jamf tracks for version currency; classic /JSSResource/patchsoftwaretitles is deprecated in its favor.
GET/v2/patch-software-title-configurations/{id}/patch-summary/versionsPer-version install counts for one patch title - quantifies how many devices still run old, unpatched software versions.
GET/v2/patch-policiesPatch policies that enforce version/deadline-driven installs; pair with GET /v2/patch-policies/{id}/logs for per-device outcomes.
GET/v1/managed-software-updates/update-statuses/computers/{id}macOS managed software-update state (download/install/available) for one computer, evidencing OS-update delivery.
GET/v2/local-admin-password/settingsJamf Managed Local Admin Passwords (LAPS) settings: auto-deploy and auto-rotation of the local admin password. Companion reads: /v2/local-admin-password/{clientManagementId}/accounts and /account/{username}/audit.
GET/v2/local-admin-password/{clientManagementId}/account/{username}/auditAudit trail of who viewed/rotated a managed local admin password - access-to-device-credentials is attributable.
POST/v2/mdm/commandsQueue an MDM command (DEVICE_LOCK, ERASE_DEVICE, ENABLE_LOST_MODE, SET_RECOVERY_LOCK, RESTART_DEVICE...) against clientData[].managementId, e.g. erase with return-to-service for device recovery. WRITE action: execute only behind human approval (D7); evidence read is the command history/audit.
GET/v1/conditional-access/device-compliance-information/computer/{deviceId}Per-computer device-compliance state surfaced to conditional access (privilege: Read Device Compliance Information) - devices must report healthy state to keep access.
GET/JSSResource/computergroups/id/{id}Classic API (instance root, no /api prefix): smart computer group definition incl. criteria (name/search_type/value) - scoping used to detect unauthorized software and gate remediation.
GET/JSSResource/policies/id/{id}Classic API: policy detail incl. general.enabled and self_service payloads - policies deliver Self Service content such as security-awareness training.
GET/JSSResource/usergroups/id/{id}Classic API: smart user group definition (is_smart, criteria, users) - role-based scoping used to target specialized training and privileged device access.

GitHub 14 endpoints · 14 controls

Auth GitHub App installation token: sign a short-lived JWT with the App's RSA private key (iss = App ID, iat/exp <= 10 min), exchange it at POST /app/installations/{installation_id}/access_tokens for a ~1 hour installation access token scoped to the org's repositories. Request read-only org + repository permissions (administration, code scanning alerts, secret scanning alerts, dependabot alerts, contents, actions, audit_log, environments, members). A fine-grained PAT is a fallback for orgs that cannot install an App.
Base URL https://api.github.com

MethodEndpointPurpose
GET/orgs/{org}/reposInventory the software, services, and systems the org manages (ID.AM-02).
GET/orgs/{org}/code-scanning/alertsList CodeQL/code scanning alerts across the org, including fixed (remediated) alerts identified by security testing (ID.IM-02, DE.CM-09).
GET/orgs/{org}/dependabot/alertsAggregate open/validated third-party dependency vulnerabilities across the org (ID.RA-01).
GET/repos/{owner}/{repo}/dependabot/alertsPer-repository dependency advisories and their remediation state to show software is maintained/replaced commensurate with risk (PR.PS-02).
GET/repos/{owner}/{repo}/attestations/{subject_digest}Fetch build-provenance/SBOM artifact attestations for an artifact digest to verify authenticity and integrity before use (ID.RA-09).
GET/orgs/{org}/rulesetsRead org-level rulesets that enforce supply-chain requirements (e.g. required dependency review and code scanning) on branches (GV.SC-05).
GET/repos/{owner}/{repo}/dependency-graph/sbomRetrieve the SPDX SBOM for a repository to monitor third-party components across the software life cycle (GV.SC-09).
GET/orgs/{org}/actions/oidc/customization/subRead Actions OIDC subject-claim customization, evidencing short-lived workload federation instead of static cloud credentials (PR.AA-03).
GET/repos/{owner}/{repo}/environmentsList deployment environments, reviewers, and deployment branch policy enforcing separation of duties for production (PR.AA-05).
GET/enterprises/{enterprise}/audit-log/streamsList configured audit-log streaming destinations, confirming log records are generated and forwarded for continuous monitoring (PR.PS-04).
GET/orgs/{org}/actions/permissions/selected-actionsRead the org's allowed-actions policy restricting which third-party Actions may execute (PR.PS-05).
GET/repos/{owner}/{repo}/branches/{branch}/protectionRead branch protection rules (reviews, status checks, admin enforcement) that gate the secure SDLC (PR.PS-06).
GET/orgs/{org}/secret-scanning/alertsList secret-scanning alerts, including push-protection bypasses and credential validity, as data/runtime monitoring (DE.CM-09).
GET/orgs/{org}/audit-logQuery the organization audit log recording investigator and administrative actions with actors and timestamps (events retained 180 days per GitHub docs) (RS.AN-06).
